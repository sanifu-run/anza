## Implementation steps

1. Implement root catalog package embedding the named data directories; internal/catalog loads that embedded filesystem. Do not attempt a go:embed path containing parent-directory traversal.
2. Generate a sorted manifest of content files/digests/provenance references and catalog version from reviewed assets. Exclude Go files and local state; generator --check is read-only.
3. Run complete reference/recipe/license/platform validation against bundled content and freeze a digest for service/CLI interoperability.
4. Generate a sanitized setup recommendation catalog artifact containing IDs, purposes, platform constraints and content version/digest only. The chat contract owner copies/pins it at build time; no executable commands/download URLs or private module dependency cross that boundary. Include Exercise entries only after the coordinator-approved schema v1 and loader validator pass. The sanitized setup catalog may include exercise IDs and manual/unsupported platform scenarios, but never executable commands or URLs.

## Acceptance criteria

- Production CLI/service use the same immutable bundled catalog digest.
- Missing asset, stale manifest, duplicate ID, unlicensed content or unknown dependency fails qualification.
- Regeneration is deterministic and contains no machine-specific paths.
- Exercise descriptors are embedded and advertised only after strict versioned schema/loader validation; unsupported and manual status is preserved.
