## Implementation steps

1. Create setupService as a consumer of the existing server/store/shared model helper, shared turn policy, and setup quota adapter. Keep the general intake prompt, booking and brief behavior intact; use a setup-specific prompt only for immutable setup-purpose conversations.
2. Use reviewed brief/machine facts as context in the existing bounded server-held history. Ask only missing setup questions through /api/ask; answers remain the existing AskResponse shape. Recommendation generation is a separate explicit setup action.
3. Embed only reviewed recommendation metadata from the sealed Anza catalog. Copy public wire fixtures with version/digest provenance into chat testdata; do not import the Anza executable or runtime-fetch a participant-provided catalog URL.
4. Generate typed Recommendation via the shared raw model helper, validate catalog IDs/platform constraints and persist exact source version/context digest. Manual steps remain plain text. Bound repair to one charged attempt under the same quota.
5. Unknown network outcome and stale versions invalidate generation safely; new setup messages/context edits invalidate older recommendations. Setup cannot book, approve a learner brief or invent a workshop agenda.
