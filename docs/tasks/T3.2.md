## Implementation steps

1. Use the existing AWS SDK/client configuration to implement a setup coordination table adapter with DynamoDB conditional transactions for request state, per-conversation allowance and setup-wide daily cost reservations. Keep these rows out of the transcript table scanned by admin/mail.
2. Reuse the existing server allow/active ceilings as an additional shared per-instance limit. New persistent caps apply to setup calls; do not claim that unchanged intake calls have a new distributed hard cap.
3. Reserve conservative configured input/output/reasoning cost in integer micro-USD before calling the shared model client. Persist running/unknown/completed idempotency state; on ambiguous outcomes retain reservation and forbid automatic paid retry.
4. Implement explicit deletion/expiry cleanup that removes session-linking payloads while retaining only minimal non-content anti-replay/budget tombstones for their disclosed TTL. Costs/model prices/caps are configuration; missing required values disable setup only.

## Acceptance criteria

- Concurrent setup requests across simulated instances cannot exceed configured setup caps or duplicate a request ID.
- A restart, timeout or day rollover preserves unresolved reservations and existing per-session allowances.
- Missing quota configuration rejects setup calls without breaking ordinary website intake; transcript scans never encounter quota rows.
