## Implementation steps

1. Define Node-based web capabilities with one recipe per exact platform artifact. Pin versions and record vendor-published SHA-256, exact byte size, origin and license. If integrity or exact size is unavailable, omit an automated recipe and leave that capability manual/optional.
2. Keep editor, GitHub CLI and browser tooling optional; select by project facts, not all-at-once defaults. Playwright is not ready without its version-matched browser payloads and system dependencies. Recipes describe one supported platform each; packs do not list mutually exclusive per-platform recipes as unconditional prerequisites. The client selects a matching recipe from supported_platforms. Where the coarse predicate cannot represent an OS/kernel floor, mark the recipe manual and state the floor in detection/verification; unknown OS-version facts never mean ready.
3. Define proposed non-destructive exercise intent in design notes only if needed to explain the pack; do not create catalog/exercises descriptors until a versioned Exercise schema and loader validator exist. Existing project package scripts require preview and separate execution consent.

Provenance JSON uses the T5.1 catalog record shape: an array of `{id, source, license}` objects referring to primary official sources and named licenses.
