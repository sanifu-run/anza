# T9.4 evidence: reproducible artifacts, integrity and CI

Status: implementation prepared; acceptance remains blocked on production updater signature verification and a generated-schema drift mechanism. Certification: NOT RUN. No production release, external publication, or native Windows execution is claimed.

## Scope and output

Worktree: isolated `task/T9.4-luna`, based on `73661c0`. Changed outputs are `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `scripts/release.sh`, `scripts/release.ps1`, `docs/release.md`, and this evidence file.

CI defines native Ubuntu, macOS and Windows jobs that run `go test ./... -count=1` and `go vet ./...`; the matching shell and PowerShell bootstrap fixtures run on native Unix and Windows runners respectively. The release workflow is manually dispatched, requires a protected `release-approval` environment before accessing signing secrets, performs native qualification before target builds, then assembles a seven-day workflow artifact. It grants read-only repository permissions and does not tag, publish or deploy. Release documentation covers backend-first sequencing, rollback, revocation and license review.

The release builder sets explicit GOOS/GOARCH, disables CGO and VCS stamping, uses trimpath and clears the Go build ID. Packaging creates per-target SHA-256 manifests, SPDX 2.3 dependency inventory, a `NOASSERTION` license inventory, stamped copies of both installers, detached Ed25519 metadata signature, and checksums. Installer sources remain unstamped. POSIX bootstrap trust remains its HTTPS-delivered embedded manifest digest. The generated signature is not wired into the Go updater.

## Verification observed

Passed locally:

- `actionlint -no-color .github/workflows/ci.yml .github/workflows/release.yml`.
- Parsed all six `schemas/*.json` files with Python JSON decoding; this checks syntax, not schema drift.
- `sh -n scripts/release.sh` and `shellcheck scripts/release.sh`.
- `python3 scripts/catalog-manifest.py --check` (catalog manifest matches source assets).
- `python3 scripts/check-plan.py` (plan validation passed).
- Synthetic packaging dry run using six fixture byte payloads and an ephemeral Ed25519 key pair under `/private/tmp`. The assembly generated 4 POSIX and 2 Windows entries, stamped the matching manifest hashes into copied installers, passed `shasum -c SHA256SUMS`, and verified the detached Ed25519 signature with its matching test public key. Two assemblies of the same fixture inputs compared byte-for-byte. The six fixture files were not compiled Anza binaries.
- Negative controls: unsupported `plan9/amd64` and an HTTP release origin were rejected; changing a packaged artifact made its checksum fail; changing signed metadata made Ed25519 verification fail.

Not observed locally:

- Native CI jobs were defined and workflow-linted but not executed here. `pwsh` is unavailable, so PowerShell fixture execution and native Windows qualification were not run.
- `sh scripts/tests/bootstrap-posix.sh` was attempted, but its loopback fixture server did not start in this restricted environment.
- `scripts/release.sh build` could not compile because required Go modules were absent from the local cache and `proxy.golang.org` DNS/network access was unavailable. Local GOCACHE was moved to `/private/tmp` before retrying; that exposed the module download failure. Thus no real platform binary build was observed.
- Broad `go test ./... -count=1` and `go vet ./...` were not run locally. The coordinator reported an active shared Mac build lease held by another session; this worker did not claim or release that lease.
- The plan/catalog checks validate the generated catalog manifest, and CI parses the six contract schema JSON files. The repository has no command that regenerates those six schemas. No schema drift guard was added or verified; the task acceptance criterion for changed generated schemas remains open.

Although the preparation workflow signs and locally verifies metadata with protected workflow secrets, this does not make `anza update` authenticate release signatures. The coordinator must assign an owned updater/key-wiring change and review the generated-schema drift mechanism before marking T9.4 acceptance complete.
