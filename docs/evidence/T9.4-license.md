# T9.4 release license bundle evidence

## Change

The release assembler now requires and copies the product `LICENSE`, `NOTICE`, and `docs/third-party-notices.md`. It includes the Go toolchain exact `GOROOT/LICENSE` and each pinned Go module exact root license and notice files from the offline module cache. `license-bundle.json` records the full source revision, toolchain version, module path/version/checksum, bundle-relative file paths, and SHA-256 hashes. The generated SPDX document leaves dependency and toolchain license expressions as `NOASSERTION`; filenames are never treated as proof of a license expression.

The helper and assembler set `GOPROXY=off`, `GOSUMDB=off`, `GOWORK=off`, and `GOTOOLCHAIN=local` while reading Go toolchain/module metadata and obtaining `go list -m -json all`. It fails closed for an unavailable or incomplete graph, an unpinned dependency, a missing module checksum, an unsupported local replacement, missing product notices, missing toolchain license, or a module without license text. Generated inventory files contain bundle-relative paths and do not record Go cache or GOROOT paths.

Darwin build requests now require the runner's native GOOS/GOARCH to match the requested macOS target, require clang, and enable cgo for the Keychain backend. They use the upstream-confirmed `keyring_no1password`, `keyring_noprotonpass`, `keyring_nofile`, and `keyring_nopass` build tags to omit unused optional keyring providers. Linux and Windows keep `CGO_ENABLED=0` and use the same optional-backend exclusion tags, retaining their native credential-store backends. The release build also injects its semantic version into `main.version`; it leaves the build timestamp unchanged.

## Limits

The actual checkout cannot currently enumerate its full pinned graph offline: `GOPROXY=off go list -m -json all` fails because `github.com/byteness/go-libsecret@v0.0.0-20260108215642-107379d3dee0` is unavailable from the module cache. No complete production dependency bundle was generated; release assembly will fail closed until the pinned graph is available in cache. Confirm the generated notices against the exact release artifacts before publishing.

The Darwin cgo build path has only been checked through synthetic command-routing fixtures. Native macOS compilation and Keychain access still require verification on matching macOS runners.
