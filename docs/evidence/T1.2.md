## Strictness follow-up

Coordinator review identified JSON `null` values being accepted for required collections/objects and unsafe relative path forms. The decoder now rejects `null` on every required top-level field; plan validation rejects null operation dependency arrays; and path validation rejects drive prefixes plus `.` and `..` segments. Added invalid cases cover null ProjectBrief constraints/known_stack, MachineFacts capabilities, Recommendation lists/maps, Plan providers and operation dependencies, Receipt owned paths, and `C:/foo`, `a/..`, `./a` and `a/./b`. The schemas and Go path checks now agree on those path forms.

After the follow-up, offline `go test ./internal/domain -count=1` and `go vet ./internal/domain` passed. With `rejectDuplicateKeys` temporarily bypassed again, `go test ./internal/domain -run '^TestRejectDuplicateKeys$' -count=1` failed as expected; the guard was restored and both scoped checks rerun green.
