## State-scoped local CLI lifecycle

A bounded change adds `ANZA_STATE_DIR` as an explicit state-root override. When present it must be a non-empty absolute path, must not contain NUL, and must not name a filesystem root. The existing `NewStore` path creation and private-permission checks continue to apply. When unset, the platform default path selection is unchanged.

Regression evidence: before the implementation, `GOCACHE=/private/tmp/anza-t103-gocache GOTOOLCHAIN=local GOPROXY=off go test ./internal/state -run '^TestUserStateRootOverride$' -count=1` failed because the function ignored the override and returned the Darwin default. After implementation, `go test ./internal/state -run '^TestUserStateRoot(Override|RejectsUnsafeOverrides)$' -count=1 -v` passed, followed by `go test ./internal/state -count=1` (`ok`, 1.459s). The rejection test covers relative, blank, NUL-containing (via the validator, since OS environment values cannot contain NUL), and filesystem-root values. Existing `TestPrivatePermissions` ran in the full green state-package suite.

The native one-package CLI binary was rebuilt from the updated source and run against `/private/tmp/anza-state-cli-t10_2/project` with `ANZA_STATE_DIR=/private/tmp/anza-state-cli-t10_2/state`. The subprocess environment contained only the explicit state directory, a temp-only empty `PATH`, `TMPDIR`, and `LANG`; no HOME or CODEX_HOME override was set, and no live credential variables were passed. The empty PATH prevented any Codex/Claude executable probe. The project was synthetic and contained a README plus harmless synthetic Codex and Claude config files. Observed local CLI flow: plan (0 operations), digest-bound review, apply (0 operations), repair (0 failures), uninstall preview, and digest-confirmed uninstall (0 removed items). All commands exited successfully; the README and both synthetic agent config files retained identical SHA-256 digests.
