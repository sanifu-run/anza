## Implementation

`catalog.Load(fs.FS)` reads only the injected filesystem, decodes a strict versioned manifest, checks payload and pack-asset SHA-256 digests, validates recipe and pack JSON with the shared v1 decoders, rejects absent license/source evidence, and checks platform predicates, IDs, paths, duplicate entries and provenance references. Pack skill IDs and prerequisite/dependency references must resolve. A deterministic depth-first walk rejects dependency cycles. `Catalog` exposes copied recipe/pack values, skill existence, version and a SHA-256 digest of normalized manifest metadata. It has no write or network API.

`catalog/manifest.json` is intentionally empty (`version: 0.0.0`): it does not assert that a recipe or skill exists. The manifest can include recipe, pack and skill entries; exercise entries are rejected with a clear error until the exercise schema and provenance representation are versioned. This follows the coordinator's scope ruling: v1 defines Recipe and Pack, not Exercise, and T1.4 has not cleared any content for bundling. The coordinator will revise T5.1 wording/index outside this worker's ownership. This work neither embeds nor seals release content; T5.7 owns final inventory sealing and export.
