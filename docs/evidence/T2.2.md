## Behavior and recovery evidence

- State roots resolve to XDG state storage on Linux, Application Support on macOS, and LocalAppData on Windows. POSIX roots, lock directories, state files, and lock files are tightened to `0700`/`0600`. Workspace identity hashes the canonical path together with device/inode on Unix or volume/file identity on Windows; canonical symlink paths match.
- Workspace and user-tool effect locks use OS-managed advisory locks. The lock owner file records PID, package process-start identity, and acquisition time. A 48-hour-old modification time does not release a live lock. Lock files persist; after process exit the OS lock is released and a later process can safely reacquire the same file. Two-scope acquisition enforces user-tools before workspace.
- JSON writes use a same-directory temporary file, private mode, file flush, atomic replacement, and directory flush on Unix; Windows uses `MoveFileExW` with replace-existing and write-through flags. An injected interruption before replacement left the prior complete document readable; a subsequent save/load recovered with the new complete document.
- Malformed, unsupported, and future-version documents return explicit errors and are not overwritten. Tests compare the original bytes after attempted replacement.

## Limitations

- Native Windows ACL creation, lock contention, process-exit recovery, and replacement durability still need a Windows runner. Linux was not tested in this task.
- The lock API provides serialization and owner identity, but callers must hold the applicable workspace/user-tool effect locks around their external mutations. Lock files remain in the private state directory and are reused after process exit; age alone never authorizes stealing.
- This task does not implement the higher-level receipt/journal semantics or recovery decisions for external package-manager effects.
