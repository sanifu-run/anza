# T9.2 POSIX bootstrap evidence

Implemented the POSIX installer and local fixture matrix. The bootstrap maps Darwin/Linux x86_64 and arm64 to release targets, supports the exact `ANZA_VERSION` override, downloads the versioned manifest and artifact, checks the pinned manifest SHA-256 before parsing, and checks the artifact SHA-256 before staging or execution. It installs under `$HOME/.local/bin`, refuses to replace an existing path unless `ANZA_UPDATE=1` is explicit, and reports the PATH setup. Default no-argument invocation uses `/dev/tty` only when that controlling terminal can be opened. Piped/noninteractive runs do not read installer stdin or start Anza.

The source digest remains `UNSTAMPED_BY_T9_4`; production execution refuses to fetch while it is unstamped. The fixture-only `ANZA_BOOTSTRAP_TESTING=1` path requires explicit local URL and synthetic manifest digest inputs and permits local HTTP only in that mode. No real download or live install occurred. The HTTPS-delivered installer remains the initial trust root; shell code does not claim independent signature verification.

`sh scripts/tests/bootstrap-posix.sh` passed 17 fixture checks on macOS: four supported OS/architecture pairs, unsupported OS and architecture, missing fetch/hash tools, bad manifest and artifact digests, interrupted transfer, existing-binary preservation, paths containing spaces, a noninteractive no-invocation check, one invocation after successful verification under a pseudo-terminal, and a local HTTPS-to-HTTP redirect rejection check using curl's production protocol flags. The test servers bind only to loopback and use synthetic shell-script artifacts.

The wget fallback was removed. GNU Wget's [`--https-only` documentation](https://www.gnu.org/software/wget/manual/html_node/HTTPS-_0028SSL_002fTLS_0029-Options.html) limits its stated behavior to recursive link following, so it does not establish a portable HTTPS-only redirect guarantee for this use. The installer now requires curl and explicitly restricts both the initial URL and redirects to HTTPS in production. The fixture keeps a successful fake wget on its controlled PATH while removing curl and confirms the installer fails without calling wget.

The negative guard check temporarily disabled the artifact digest comparison. The fixture matrix then failed as expected with `FAIL: bad_artifact_digest unexpectedly passed`; the original installer was restored and the full suite passed again.

Verification passed: `sh -n install.sh`, `sh scripts/tests/bootstrap-posix.sh` (17 checks), `shellcheck install.sh scripts/tests/bootstrap-posix.sh`, and `git diff --check`. ShellCheck was available and reported no findings after cleanup. Release digest stamping and production release publication remain T9.4 work; no target-platform install qualification is claimed.
