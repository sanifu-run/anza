## Outcome

The adapter accepts the exact Codex version `0.157.1`, listed as current stable in the compatibility snapshot, and returns `documented_only` evidence. Other, missing, or decorated versions return an explicit `unsupported` result with no config or skill operations. This exact-version gate does not mean Codex or OpenRouter was installed or qualified on this machine.

Native subscription mode plans no Codex config edit and exports no credential. For an explicit OpenRouter choice, the adapter produces a TOML edit tagged `launch_profile_only`; callers must not apply it to global Codex config. It uses the documented Responses endpoint and wire type, a participant-selected full model slug, and a static auth command only when the caller identifies a documented POSIX or PowerShell shell. Missing or unsupported shells remain unsupported rather than being guessed. The only credential value exposed by the adapter is the symbolic environment name `OPENROUTER_API_KEY`; the request has no key field. Existing user-owned profile values conflict instead of being replaced. The adapter returns managed skill copy intents only under the project-relative `.agents/skills/<skill-id>/SKILL.md`, with a preserve-existing policy; it never copies or edits `AGENTS.md`.
