# T8.1 evidence: catalog and binary update planning

Implemented a read-only release metadata check and pure update-plan builder in `internal/lifecycle`. Metadata is checked against its SHA-256 digest and an injected signature verifier before decoding. Planning compares binary/catalog versions, protocol compatibility, migration effects, and recorded/current managed-file hashes. It returns conflicts for edited managed content and rejects replay or unapproved downgrades. The package does not download artifacts, write installation state, replace binaries, or execute updates.

The package uses only the Go standard library. Source and signature verification are injected, so verification used local fixtures and made no network or service calls.

## Verification

- `go test ./internal/lifecycle -run TestUpdate -count=1`: passed; all five `TestUpdate*` cases passed.
- `go vet ./internal/lifecycle`: passed.
- `gofmt -d internal/lifecycle/update.go internal/lifecycle/update_test.go`: no output.
- `git diff --check`: passed.

## Red/negative evidence

With the metadata-digest comparison deliberately disabled, `TestUpdateIntegrityFailure` failed as predicted: `Check() error = <nil>, want ErrIntegrity`. The guard was restored, and the complete `TestUpdate` run passed afterward.

The first pre-implementation package test could not compile because the owned package/API did not yet exist; it did not provide a behavioral baseline. The guard-disabled run above is the behavioral negative check.

## Limits and handoff

This task produces verified metadata and a reviewable plan only. Artifact fetching, installation/replacement, post-install version checks, and receipt updates remain for the owning update execution task. No live release signature or production installation was tested.
