# T8.1 evidence: catalog and binary update planning

Implemented a read-only release metadata check and pure update-plan builder in `internal/lifecycle`. Metadata is checked against a well-formed, declared SHA-256 digest and an injected signature verifier before decoding. The declared digest must match the payload digest. Planning compares binary/catalog versions, protocol compatibility, migration effects, and recorded/current managed-file hashes. It returns conflicts for edited managed content and rejects replay or unapproved downgrades. The package does not download artifacts, write installation state, replace binaries, or execute updates.

The package uses only the Go standard library. Source and signature verification are injected, so verification used local fixtures and made no network or service calls.

The guard now checks both SHA-256 hex format and payload-digest equality. `TestUpdateIntegrityFailure` supplies a well-formed but incorrect 64-character digest and also checks signature rejection.

For the corrected negative check, I temporarily disabled the working digest guard. `TestUpdateIntegrityFailure` then failed as predicted: `Check() error = <nil>, want ErrIntegrity`. ## Limits and handoff

This task produces verified metadata and a reviewable plan only. Artifact fetching, installation/replacement, post-install version checks, and receipt updates remain for the owning update execution task. No live release signature or production installation was tested.
