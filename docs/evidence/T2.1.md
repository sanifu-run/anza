# T2.1 evidence: read-only platform inspection

## Outcome

Implemented platform fact collection, a fixed two-entry CLI version-probe catalog, and a separately consent-gated reader for selected project manifests. Inspection APIs return minimized facts and parsed versions only; they do not return paths, raw command output, or manifest contents. Manifest parsing does not execute package scripts. No live project or installed-tool probes were performed during this task.

## Owned files

- `internal/platform/inspect.go`
- `internal/platform/detect.go`
- `internal/platform/inspect_test.go`
- `docs/evidence/T2.1.md`

## Test-first and negative evidence

The acceptance tests were authored before implementation. The first scoped run was red at compile time because the inspection API and its supporting types/helpers did not yet exist. After implementation, the suite passed.

The consent guard was then deliberately disabled in `InspectProject` and `TestManifestConsentPrecedesRootAccess` was run against a nonexistent synthetic root. It failed as predicted: the callback ran, then inspection reached root access and returned `workspace root is unavailable` instead of `ErrConsentDenied`. The guard was restored before final verification; the same test passes in the final suite.

## Final verification

Both commands used temporary `HOME` and `GOCACHE` directories with module/network resolution disabled. They were scoped to the one owned package:

```text
HOME="$test_home" GOCACHE="$test_cache" GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local go test ./internal/platform -count=1
ok   github.com/sanifu-run/anza/internal/platform  0.358s

HOME="$test_home" GOCACHE="$test_cache" GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local go vet ./internal/platform
exit 0
```

The test suite covers read-only synthetic roots; consent before root access; script non-execution; selected, minimized stack IDs; supported and unsupported OS/architecture cells including Windows/arm64 facts; symlinked roots and parents; supported, unsupported, and unknown filesystem outcomes; fixed probe arguments; missing, failed, malformed, timed-out, oversized, and successful version probes. Temporary projects are created by `t.TempDir`; executable lookup and execution are injected test functions.

## Boundaries and limitations

- `Inspect` was not invoked against the current checkout or any participant workspace. No project manifest/package script or installed command was inspected by this task.
- `InspectProject` invokes a consent callback before filesystem/root access and reads only selected allowlisted manifest names. It recognizes allowlisted package-manager/framework IDs and ignores script fields.
- Runtime OS version is `unknown` where the implementation has no standard-library source; Linux reads only `/etc/os-release`. macOS and Windows filesystem type may remain `unknown` rather than being guessed. Generic Windows/arm64 facts are reported; vendor-specific support remains a separate qualification decision.
- These are synthetic unit tests, not native VM qualification on each operating system.
