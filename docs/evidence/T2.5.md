# T2.5 evidence

Date: 2026-09-28. Status: implementation draft; validation deferred.

## Source review

The pinned `99designs/keyring` v1.2.2 source was reviewed as a platform
implementation reference on 2026-09-28:

- macOS `keychain.go` is gated by `darwin && cgo` and calls
  `github.com/99designs/go-keychain` for Security.framework operations.
- Windows `wincred.go` delegates generic credential operations to
  `github.com/danieljoos/wincred` and prefixes targets with the configured
  service name.
- Linux `secretservice.go` depends on `github.com/godbus/dbus` and
  `github.com/gsterjov/go-libsecret`; its init path declines to register the
  backend when the session bus is unavailable.

The implementation uses the coordinator-approved `github.com/byteness/keyring
v1.13.2` API, pinned on 2026-09-28. The package page reports MIT licensing,
publication on 2026-09-15, a maintained-fork status, and best-effort
maintenance. It provides the native macOS Keychain, Windows Credential
Manager, and Linux Secret Service backends, along with other optional stores
and provider integrations. That broad surface and dependency tree are material
tradeoffs. Runtime selection is constrained to one backend for the current
`GOOS`, with service name `anza`; no automatic backend selection or file
fallback is used. The coordinator owns the dependency pin, sums, and required
compile-time opt-out tags.

Package documentation lists these opt-out tags for non-native backends:
`keyring_nofile`, `keyring_nopass`, `keyring_nopassage`,
`keyring_no1password`, and `keyring_noprotonpass`. `keyring_noprotonpass` is
documented in the Proton backend section. The tag set must be supplied by
repository build/test configuration; the `AllowedBackends` runtime list is an
independent restriction.

## Implementation and limitations

The package API scopes IDs to a provider and workspace, derives opaque Anza
targets, redacts secrets and IDs in formatting/JSON, sanitizes backend errors,
copies secret buffers at store boundaries, and provides a session-only memory
store. The platform factory allows only Keychain on macOS, WinCred on Windows,
and Secret Service on Linux. A failed or unsupported native backend returns a
session store together with `ErrUnavailable`, so callers can continue only
after observing that persistence is unavailable. Native keyring calls are not
part of unit tests.

No CLI masked-input seam is included because its caller is outside the owned
paths for T2.5. No real credentials, keychains, provider accounts, or vendor
logins were accessed or modified.
