## Outcome and boundaries

`Apply` verifies the plan by strict domain decoding and recomputing its canonical digest, requires an exact digest-bound approval for the current `plan-review-v1` disclosure and verifies its approval time is current, acquires the state store's ordered user-tool/workspace locks, validates every operation and typed payload, and preflights all targets before journaling or performing the first effect. It then rechecks each preimage immediately before the injected effect boundary. The effect methods receive the expected preimage hash and are required to enforce it atomically, closing the race between inspection and mutation.

The executor accepts only the current planner operation kinds: `write_config` with a `configedit.Edit`, and `install_artifact` with bytes whose SHA-256 matches the approved postimage. Unknown kinds, target roots, unsafe paths, symlinks, non-regular files, changed preimages, unplanned payloads and mismatched output hashes fail closed. There is no shell or process payload. Adapter-created operations are not added after approval.

Receipts journal `planned`/`running`/terminal states around every effect, pre/post digests, logical owned paths and config keys, backup references, timestamps and manual reconciliation. Config preimages and the exact `configedit.Edit` metadata are persisted privately before an effect; recovery can reload that edit after process restart. Recovery classifies a running effect from the current target: exact postimage means success without repeating the effect; exact preimage permits resume under the same current approval; any other target is preserved and marked for manual reconciliation. On later-operation failure, reversible config edits are inverted only when their exact approved postimage is still present; participant changes are preserved and recorded as rollback conflicts. Artifact paths are recorded as owned outputs.

Tests use only synthetic plans, config bytes, artifact bytes, in-memory CAS effects, injected crash points, and temporary state roots. No project/config was inspected, no filesystem install or network download ran, and no provider/account call occurred.
