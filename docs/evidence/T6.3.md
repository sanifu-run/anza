## Outcome and boundaries

The adapter plans either native subscription mode or an explicit OpenRouter child-process launch environment. It emits intents only: it does not read or write Claude settings, `CLAUDE.md`, auth caches, or skill files. Subscription mode leaves native login/config untouched. OpenRouter mode requires an explicit `AuthNone` state and no provider auth keys in the supplied settings; unknown state is manual and cached subscription state or conflicting settings produces a conflict with no environment assignments. The conflict result describes the key names only. The adapter never logs out or deletes cached credentials.

OpenRouter launch variables are limited to the documented base URL, a symbolic `OPENROUTER_API_KEY` credential reference, and an explicitly blank competing API-key variable. The full model slug is passed as a validated `--model` argument. This is a launch descriptor, not proof that the selected model or its tools work with Claude Code. All results are `documented_only`; the adapter accepts only the exact version recorded in the compatibility snapshot and reports other versions unsupported.

Managed skill copy intents are limited to project `.agents/skills` and `.claude/skills` logical roots and preserve existing files. Duplicate physical identities collapse to one deterministic root. The adapter accepts an opaque physical identity supplied by its caller; it does not inspect symlinks, discover directories, copy assets, or handle global roots. The caller must provide a correct physical identity from an authorized read-only discovery layer. Existing `CLAUDE.md`, hooks, and permission settings receive no intents or writes.
