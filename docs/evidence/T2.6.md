## Behavior and limitations

`Plan(existing, Patch)` returns bytes, preimage/postimage SHA-256 hashes and per-key before/after ownership metadata without file I/O. A nil input represents a missing file; empty existing JSON is rejected as malformed. Existing values that differ from the requested value are changed only when the caller supplies a matching previously-owned value in `Patch.Expected`; otherwise the operation returns `ErrConflict`. Existing values already equal to the requested value are left untouched and are not claimed as Anza-owned.

`Inverse(current, applied)` checks each Anza-owned key against its recorded postimage, restores or removes only unchanged values, and reports changed values in `SkippedKeys`. It preserves unrelated bytes and does not restore a whole-file backup.

JSON uses a standard-library syntax scanner over a validated single object. TOML is deliberately conservative: it supports bare dotted keys, simple table headers, strings, booleans, numbers and scalar arrays while preserving comments and line formatting. Duplicate keys/tables, malformed values, array-of-table blocks, inline tables, multiline strings/arrays, quoted keys and unsupported date/time values are refused rather than rewritten. A parent object/table must already exist for nested edits; unknown syntax and key conflicts return an error so callers can present a manual diff. No config file has been applied to a real user environment.
