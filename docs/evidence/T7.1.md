# T7.1 evidence: independent provider launch choices

Implemented the launch boundary in `internal/launch/launch.go`. Provider choices are resolved by workspace and agent. OpenRouter credentials come from the workspace-scoped credential store or an injected/session environment lookup and enter only `process.SensitiveEnv`; Claude's endpoint and empty API-key override and Codex's workspace `CODEX_HOME` are also child-only values. Native subscription launches invoke the requested vendor CLI without reading or exporting its login state, provide the supported interactive login guidance, and always report `Authenticated: false`.

The fixtures use synthetic stores, environment lookups and child test processes. Coverage includes all four workspace/agent provider combinations, Claude and Codex OpenRouter child environments, secret-free args/receipts, unchanged parent environment, literal argument forwarding, missing credentials, Claude auth conflict handling, and native-launch cancellation. The tests did not run an installed vendor CLI, make a provider request, install software, or access native credentials.

Receipt follow-up: `Result` serializes only the argument count. Caller argv still reaches the runner unchanged, while a synthetic token-like argument is verified in the child and absent from the JSON result. The OpenRouter credential is also checked absent from argv and receipts.
